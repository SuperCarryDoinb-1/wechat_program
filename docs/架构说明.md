## 结构与依赖方向

```text
pages/*/*.js                         三个微信原生路由入口
  └─ utils/page-flow.js              组装入口，保持旧调用方式
       ├─ utils/screens/registry.js  注册视图、邀请入口和返回规则
       └─ utils/flow-runtime.js      挂载、生命周期、事件转发、旧回调隔离

utils/screens/
  ├─ index.js                       首页编排
  ├─ quiz.js                        答题状态机与提交编排
  ├─ result.js                      结果恢复、揭晓、导航、授权生命周期
  └─ result/
       ├─ content.js                解读与配对展示状态、异步更新
       └─ poster.js                 海报交互、导出缓存、相册提示

utils/*-service.js / pair-result.js  应用服务
utils/result-store.js               当前结果缓存的唯一读写入口
utils/poster.js / privacy.js        平台适配
utils/scoring.js / pairing.js / …   纯规则、校验、分享载荷、绘图
config/                            题库、文案、素材路径和参数

pages/*/*-view.wxml、*-view.wxss     各业务视图和样式
utils/flow-view.wxml、flow-view.wxss 视图和样式的公共装配
components/                        类型卡、坐标图、宠物组件
cloudfunctions/                    三个独立部署的云函数
tests/、docs/                      本地验证与维护文档，不进入小程序包
```

流程内核通过参数接收视图和业务规则，不直接导入首页、答题或结果模块。`registry.js` 负责业务规则，`page-flow.js` 负责组装。

页面控制器可以调用服务和纯逻辑，服务不能导入页面、组件或控制器。配置只能引用配置。评分、配对、公开结果校验、内容校验、分享载荷、海报绘制、宠物运动及行为模块可脱离微信平台运行。

保留现有 `utils/` 路径，避免目录改名牵动测试、预览工具及云函数同步。模块职责以依赖边界和测试约束落实。

## 页面容器与状态所有权

`app.json` 中三个路由继续有效。实际界面由同一个 Page 容器内部切换，此次未恢复为三次原生页面跳转。

| 状态 | 所有者 | 释放或更新时机 |
| --- | --- | --- |
| 当前视图、挂载状态、页面滚动位置 | 流程内核 | 视图切换或 Page 卸载 |
| 未完成答案、切题计时器、提交锁、答题宠物 | 答题控制器 | 退出视图；后台暂停相关活动 |
| 当前结果、详情展开、揭晓计时器 | 结果控制器 | 退出结果视图 |
| 解读和配对展示状态 | 结果内容子模块 | 随视图销毁；迟到响应检查 `_disposed` |
| 海报路径、导出锁、清晰度、相册引导 | 结果海报子模块 | 随视图销毁，不跨测试轮次共享 |
| 同轮内容请求和已返回内容 | 内容服务 | 按 `requestId` 复用，后续请求替换 |
| 最近一次完整结果 | 结果存储模块 | 新一轮完整提交覆盖；内容只回写匹配请求 |

每次进入视图都复制初始数据。子模块提供初始字段和方法，运行状态仍由当前视图实例持有，没有跨页面共享的海报或配对状态。

`_view` 保留真实 Page 实例供 Canvas 查询。`setData` 挂载回调、`onShow` / `onReady` 顺序以及旧视图失效保护维持原有逻辑。

## 存储与异常约定

`utils/result-store.js` 提供三个操作：

- `read(platform)`：读取当前键，版本不支持返回 `null`，读取异常交给调用方处理。
- `write(platform, record)`：按原格式写入；异常继续抛出，答题页保留答案并提示重试。
- `saveContent(platform, record, content)`：最新缓存的 `requestId` 匹配才回写内容；缓存失败不妨碍展示。

键名和版本仍来自 `config/quiz.js`，未增加迁移、历史记录或新字段。评分由 `scoring.js` 执行。恢复旧结果时补充请求 ID 的写入失败可以忽略，正常提交失败则必须阻止进入结果页，这两种错误语义不能合并。

## 增加或移除模块

### 增加独立视图

1. 在 `utils/screens/` 添加控制器，初始字段放在 `data`，定时器、监听和异步工作在生命周期内管理。
2. 在 `utils/screens/registry.js` 注册，并维护必要的入口或返回规则。
3. 添加 WXML / WXSS，在 `utils/flow-view.wxml`、`utils/flow-view.wxss` 装配。所用组件需在三个路由的 JSON 中注册，因为三个入口都可承载全部视图。
4. 使用现有 `_flow.go(stage, options)` 进入。仅需要新的外部路由时才追加 `app.json` 和原生入口文件。
5. 补充新业务路径验证并运行全量测试；无需修改流程内核。

### 增加结果页能力

参考 `utils/screens/result/poster.js`，把同一能力的字段和方法放在一起，平台和服务依赖由结果页组装时传入。海报模块通过 `getPoster` 延迟取用导出器，首次进入结果页仍不加载导出模块。

新方法和状态名不能覆盖已有模块。拥有定时器或监听的能力必须由结果页显式接入生命周期清理；当前组合方式不会自动调用子模块生命周期。不要依靠对象展开顺序覆盖 `onLoad` 或 `onUnload`。

### 移除能力

删除相应入口、模板事件及组件使用，再移除模块装配、调用点和确认无消费者的配置 / 素材。可选结果能力主要影响结果控制器及对应子目录；独立视图主要影响注册表、视图装配和进入它的导航。

首页、答题、结果是当前完整业务链，不能只删注册项就认为业务仍成立。移除核心模块属于后续功能变更，需同时定义新流程和分享入口。此次没有移除这些模块。
