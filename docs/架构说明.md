# AITI 代码架构

更新日期：2026-09-12。本次整理保持原生微信小程序结构，不增加框架或运行时依赖。

## 职责划分

| 模块 | 职责 |
| --- | --- |
| `pages/` | 首页、答题、结果的页面状态、生命周期与交互编排 |
| `components/` | 类型卡片、坐标图的展示 |
| `config/` | 题库、人设、文案、素材路径和运行参数 |
| `utils/scoring.js`、`pairing.js` | 评分与双人配对规则 |
| `utils/content-validation.js`、`public-result.js` | 内容和公开结果校验 |
| `utils/content-service.js` | 解读请求、缓存与失败兜底 |
| `utils/friend-service.js` | 查询朋友公开结果、校验与超时处理 |
| `utils/pair-result.js` | 组合本人和朋友结果，构建双人展示数据 |
| `utils/sharing.js` | 判断是否可携带结果 ID 分享，组装标题、路径和封面 |
| `utils/poster-renderer.js` | 个人、双人海报及封面的 Canvas 绘图 |
| `utils/poster.js` | 微信画布获取、素材加载、图片导出和相册保存 |
| `utils/privacy.js` | 隐私授权监听、同意/拒绝、页面卸载清理与隐私指引打开 |
| `utils/navigation.js` | 页面跳转及答题链接组装 |
| `utils/cloud.js` | 云环境初始化与开发诊断 |
| `cloudfunctions/` | 云端解读生成、公开结果读取和诊断 |

页面调用服务完成交互；服务复用规则与配置。评分、配对、分享数据组装和绘图不直接调用微信 API。绘图接收 Canvas 上下文，既能在小程序使用，也能用于本地校样。

## 本次调整

- 从分享模块拆出朋友查询，双人结果无需依赖分享功能。
- 从海报模块拆出绘图；渲染参数集中在 `config/poster.js`，分享和保存提示保留在 `config/sharing.js`。
- 合并个人、双人海报重复的底板和坐标轴绘制，保留绘制顺序与样式。
- 首页与结果页复用隐私指引处理，结果页统一管理授权监听的注册和释放。
- 页面提示与实际分享共用资格判断；重新测试与普通开始测试共用答题链接生成。
- 清理未使用的跳转方法、文案和重复隐私提示；PRD、待办清单不参与小程序打包。
- 包体预检纳入根目录普通文件，避免遗漏新增文档的体积。

## 维护约定

1. 页面保留与交互直接相关的状态；跨页面复用或可独立验证的逻辑才提取模块，不为单次调用增加抽象层。
2. 业务规则先修改源配置与纯逻辑，不在页面、分享或海报中重复实现评分。
3. 云函数独立部署，`shared/` 中的副本是部署所需。修改共享源文件后执行 `node tests/sync-cloud.js`，再运行回归；测试检查副本一致性。
4. 新增根目录非运行文件时同步检查 `project.config.json` 的排除规则。源码体积统计不能替代开发者工具的实际包体结果。

## 验证与边界

执行 `node tests/run.js` 检查评分、页面交互、云调用替身、分享、海报、隐私生命周期及模块依赖。新增依赖检查要求前端引用存在、无循环，并防止分享和绘图重新依赖平台服务。

架构整理完成时，逐项比较了 8 种个人海报和 64 种有序双人组合的绘图指令，均与整理前一致。这是当时的本地记录上下文比较，不是真机截图验收。随后同日的视觉改版主动更新了绘图样式，最新视觉及验证方式见 [UI 设计说明](UI设计说明.md)。

执行 `node tests/release-audit.js` 更新本地发布预检。当前仍为模拟模式，云开发尚未开通；真实云、模型、微信编译、相册和双账号回流仍按原验收清单处理。本次未变更题库、评分、人设、AppID 或上线状态。
