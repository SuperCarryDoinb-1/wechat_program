# 页面切换优化（2026-09-15）

## 当前实现：开始、答题、结果在同一页面内切换

根据反馈，题目之间很快，而开始测试和结束答题仍慢。本轮将这两个边界的 `navigateTo` / `redirectTo` 改成页面内视图切换，保留三个原有路由作为兼容入口。

- `utils/page-flow.js` 管理当前视图、页面前后台状态和事件转发。
- `utils/screens/` 保存三个视图的业务逻辑；`pages/*/*-view.wxml` 与 `*-view.wxss` 保存原有布局和样式。
- 首页点击开始直接切到第一题；最后一题保存成功后直接切到结果；重新答题创建全新的答案状态。完整流程不调用微信路由 API。
- 切换时释放旧视图的宠物定时器、布局回调和隐私授权监听；视图挂载后才启动新视图交互。晚到的内容请求不会写入已经退出的视图。
- “返回首页”入口保留在现有页头：答题页利用页头顶部空间定位按钮，结果页与品牌排在同一行；不额外插入顶栏或推低正文。内部切换仍不增加微信页面栈。
- 三个路由入口均注册宠物、类型卡片和坐标图组件；答题继续使用原生宠物图片。分享按当前视图生成，收到邀请仍进入首页，不显示接收者的本地旧结果。
- 结果画布仍按需创建，节点查询使用真实微信 Page 实例。

### 本轮验证

- `npm test`：109 项通过。新增真实入口脚本集成测试，验证完整流程路由调用次数为 0、清空答案、前后台恢复、过期回调、分享邀请、存储失败重试和海报保存。
- 全部 WXML / WXSS 经本机开发者工具附带编译器编译通过。
- `node tests/check-flow-wxml.js` 执行实际 WXML 编译产物：三个路由入口都能渲染首页、四选项答题和结果，再切回首页；验证宠物节点、模板数据作用域、组件注册及按需画布。
- 上述验证不包含模拟器修改后耗时或真机帧率，不将“无路由调用”换算成未经测量的提速比例。

重新编译后，从首页连续检查“开始测试 → 12 题 → 结果 → 重新答题”，期间不手动重新编译。应在同一个原生路由中完成整个流程。首次启动开发者工具时仍可能进行基础库联网检查。

## 本次修改

- 在 `project.config.json` 增加 `watchOptions.ignore`，排除测试、输出、文档和工作目录元数据。已从本机开发者工具的文件监听实现确认支持此配置；运行页面、组件、配置和资源仍正常监听。
- 宠物组件在首页、结果页分别注册。答题页保留原生宠物图片和原有控制器，移除它不使用的全局组件依赖。
- 页面初始数据只包含当前视图使用的文案及图片配置。
- 答题选中状态与切换状态合并更新，反馈等待由 200 ms 改为 120 ms；已经位于顶部时不再调用滚动接口。保留重复点击、旧题事件、隐藏和卸载保护。
- 答题完成后保存记录即跳转，内容服务由结果页加载，减少跳转前的同步存储工作。
- 结果页合并初始结果更新；保存海报时才加载绘图模块、挂载画布，并等待视图更新回调后查询画布。卸载后取消后续导出。
