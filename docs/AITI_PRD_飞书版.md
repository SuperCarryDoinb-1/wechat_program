## 2. 产品背景与定位

### 2.1 产品概述

AITI 用 12 道日常情境单选题，让用户了解自己如何使用 AI，并获得一个有记忆点的“AI 身份证”。结果包含三字母身份、角色人设、简短点评、使用建议，以及与 AI 相处的二维坐标。用户可以保存个人海报，向好友发起测试邀请，并在好友完成测试后展示双人关系。

首页核心表达为：**12道题解锁你的AI身份证**。

这是娱乐型自我表达与社交测试。固定免责声明为：**仅供娱乐，结果不构成任何评价**。不应把结果解释为心理诊断、能力排名或具有科学效度的人格测量。

### 2.2 用户与场景

以下用户分类是基于现有功能的产品分析，不代表已完成访谈或用户调研。

| 用户 | 使用场景 | 核心需求 |
| --- | --- | --- |
| 日常 AI 使用者 | 工作、学习或生活中接触 AI | 快速获得对自己使用方式的有趣描述 |
| 轻度接触或对 AI 保持距离的人 | 对新工具好奇、被朋友邀请 | 无须专业知识即可完成测试 |
| 社交分享用户 | 群聊、好友对话、朋友圈传播 | 获得有表达欲的身份卡和可分享图片 |
| 受邀好友 | 从某人的分享进入 | 了解邀请人的身份，测试后查看两人的关系 |

### 2.3 产品价值

1. 低参与门槛：没有手机号、头像昵称填写或自由文本输入环节，进入即可答题。
2. 结果稳定：相同答案产生相同类型、分数和坐标；AI 不参与最终分类。
3. 内容有变化：真实模型可结合具体答案生成一句点评与三条建议。
4. 具备社交链路：分享者提供邀请，受邀人完成测试后生成配对关系，并继续邀请下一位朋友。
5. 失败仍可完成：网络或模型不可用时保留本地测评与静态解读。

### 2.4 产品目标与边界

| 项目 | 目标或范围 | 当前口径 |
| --- | --- | --- |
| 测试长度 | 固定 12 题，每题 4 选 1 | 当前实现 |
| 体验时长 | 期望约 90 秒完成 | 体验目标，不是已测平均值，不设置倒计时 |
| 身份类型 | 8 种，含 1 种隐藏款 | 当前实现 |
| 结果可用性 | 离线仍可产出个人结果 | 当前实现 |
| 真实分享 | 已获得云端结果 ID 时携带本人结果 | 当前实现，真实环境待验收 |
| 双人关系 | 8 × 8 共 64 种有序组合 | 当前实现，规则对交换顺序保持对称 |
| 商业化 | 无支付、广告、订阅、付费解锁 | 不在当前范围 |
| 用户系统 | 无个人中心、历史列表、头像昵称体系 | 不在当前范围 |
| 社区与运营后台 | 无动态、评论、排行榜和后台编辑页面 | 不在当前范围 |
| 通用 AI 聊天 | 无聊天窗口、模型切换或提示词输入 | 不在当前范围 |

首页 ChatGPT、Claude、DeepSeek、Kimi 为视觉展示文字，不是四个可点击的模型服务入口，也不代表项目已集成四种模型。

## 4. 信息架构与用户流程

### 4.1 页面结构

| 页面 | 路由 | 职责 |
| --- | --- | --- |
| 首页 | `/pages/index/index` | 产品介绍、邀请人展示、开始测试、隐私指引 |
| 答题页 | `/pages/quiz/quiz` | 在同一页面内逐题展示并保存本轮内存答案 |
| 结果页 | `/pages/result/result` | 个人结果、解读、详情、配对、分享和保存海报 |

不使用 TabBar。所有 12 道题都在同一个答题页切换，不创建 12 个路由。

### 4.2 普通测评流程

进入首页 → 点击“开始测试” → 从 Q1 开始 → 每题选择一个选项 → 完成 Q12 → 本地计分 → 保存本轮完整结果 → 启动解读请求 → 立即进入结果页 → 展示身份与解读骨架 → 展示 AI 或静态解读 → 保存海报、分享或重新测试。

进入结果页不等待模型返回。

### 4.3 好友邀请流程

A 完成测试并取得有效云端结果 ID → A 分享包含自己 `rid` 的链接 → B 从首页查看 A 的类型 → B 开始测试，邀请 ID 转为 `fromRid` → B 完成测试并取得自己的云端结果 → 云端确认 A 的类型 → B 再查询 A 的公开分数并校验 → 展示 B 与 A 的双人卡 → B 再分享时携带 B 自己的 `rid` → C 受邀后与 B 配对。

配对属于结果页中的区域，不是独立页面；转分享不传播完整的 A、B 双人报告。

### 4.4 中断与重新测试

- 返回上一题：保留本轮全部已答选项，可修改，不丢失后续已答题。
- 切到后台：暂停等待切题的计时器；回前台后继续一次切题。
- 真正退出答题页：丢弃本轮草稿，下一次从 Q1 开始。
- 中途退出不覆盖上一次完整结果。
- 从结果页重新测试：新建本轮答案；如果本结果来自好友邀请，继续携带该好友的 `fromRid`。
- 从普通首页开始：不继承上一轮的邀请关系。

## 5. 首页需求

### 5.1 展示顺序

1. 顶部 AITI 品牌字样，以及“与 AI 共生”标签。
2. 单行主标题“12道题解锁你的AI身份证”。
3. 如携带邀请参数，展示好友类型提示条。
4. 蓝底主视觉卡，展示黄色 A 与紫色斜向 I 组成的 AI 字形角色。
5. 四个卡通助手形象组成的横向图片，下方依次为 ChatGPT、Claude、DeepSeek、Kimi。
6. 黄色“开始测试”按钮。
7. 隐私保护指引入口。
8. 仅开发诊断开关开启时，追加诊断区域和开发阶段说明。

当前首页没有八类身份轮播、历史报告入口、模型选择器；配置中保留的“约 90 秒”等统计文案，不等于当前首页正在展示这些模块。

### 5.2 开始测试

| 条件 | 行为 |
| --- | --- |
| 普通点击 | 打开答题页，从 Q1 开始 |
| 首页 URL 有合法 `rid` | 答题页参数为 `fromRid=该 rid` |
| 连续点击 | 在一次打开动作结束前只允许发起一次跳转 |
| 跳转失败 | 提示“页面打开失败，请重试”，解除锁定 |
| 从答题返回首页 | 解除开始按钮锁定 |

### 5.3 邀请提示

- URL 包含 `rid` 时，显示“正在读取朋友的类型…”。
- 查询成功后显示“你的朋友是【类型名称】”。
- 非法、删除、网络异常或超时，显示“暂时无法读取朋友的结果，你可以先测测自己的类型。”。
- 查询未完成也允许开始答题，合法邀请 ID 继续随流程传递。
- 页面卸载后不得用异步响应修改页面。

### 5.4 朋友圈单页模式

当前实现以启动场景值 `1154` 判断单页模式。该模式显示“点击微信提供的「前往小程序」，查看邀请并开始测试。”，隐藏开始按钮及隐私入口，不执行页面跳转或好友查询。

从结果页带 `rid` 或 `invite` 进入时，优先按邀请处理，不能读取访问者设备中缓存的旧结果。完整小程序环境下重启到首页，单页环境下只展示邀请说明。

此处描述现有分支逻辑；平台实际打开行为必须在目标微信版本验证。

## 6. 答题需求

### 6.1 页面内容

| 区域 | 内容与规则 |
| --- | --- |
| 页头 | AITI 品牌、当前情境序号和总题数，如“情境 1 / 12” |
| 进度条 | `四舍五入(已作答题数 / 12 × 100)%`；依据已作答数，不是当前题序 |
| 场景条 | 对应场景小图及标题，缺图片时显示代码绘制图形 |
| 题目 | 完整显示当前题干 |
| 选项 | 固定 A、B、C、D 四项，单选 |
| 页面底部 | “上一题”与“下一题”；最后一题为“查看结果” |
| 错误区域 | 显示提交失败原因和“重试查看结果”按钮 |

### 6.2 选择与切题

1. 初始答案为 12 个空值，初始选中项为无。
2. 点选后立即更新答案、选中背景和进度。
3. 约 200 毫秒后自动进入下一题；最后一题自动提交。
4. 等待切题期间禁用选项和下一题，屏蔽重复点击与旧题事件。
5. 第一题“上一题”禁用；其他题可以返回，等待中的自动切题应被取消。
6. 未选择时“下一题”禁用；返回已答题时保留已选状态，可以直接下一题，也可改选。
7. 切题滚动回顶部，避免上一题的滚动位置导致新题不可见。
8. 答案修改后，提交时重新累计全卷，不在旧分数上重复加减。

场景背景和选中背景从 `#C9B6FF`、`#A8C7FA`、`#FFE17D`、`#FFD1BC`、`#BCE8CC`、`#F8C4DF` 中随机选择，排除紧邻上一次使用的颜色。颜色随机不影响结果。

当前选项字母框在选中时显示字符“?”；这是模板中的现有显示，不应把历史文档中的“勾选图标”当作当前事实。正式优化时可将其替换为明确选中符号。

### 6.3 提交顺序与错误

| 步骤 | 成功结果 | 失败处理 |
| --- | --- | --- |
| 校验并计算 12 题答案 | 获得类型、三维分数、坐标和稀有度 | 提示“暂时无法整理结果，请返回上一题后重新选择。” |
| 保存本地完整结果 | 更新最近一次结果，关联本轮请求 ID | 提示“结果暂时没能保存，你的选择还在。请重试。”；不进入结果页 |
| 启动解读 | 同一本轮请求可供结果页复用 | 不阻塞本地结果跳转；由内容服务降级 |
| 跳转结果页 | 使用替换当前页方式进入 | 提示“结果已经保存，页面暂时没打开。请重试。” |

失败解除提交锁；重试保留当前答案。未修改答案的同轮重试复用请求关联 ID。

### 6.4 小屏现状与验收差异

页面采用自然纵向滚动，底部答题导航处于文档流中。当前选项文字样式为单行、超出省略号；较长选项在小屏上可能无法完整读取。复现当前版本时应保留这一现状记录；正式验收建议改为完整换行并实测 320 × 568、375 × 667 和常用大屏，不能仅依据自动测试宣称文字已全部可读。

## 7. 评分、类型与坐标

### 7.1 三个维度

| 维度 | 字段 | 负方向 | 正方向 | 字母位置 |
| --- | --- | --- | --- | --- |
| 与 AI 的关系 | `rel` | T：工具 | P：伙伴 | 第 1 位 |
| 对 AI 的态度 | `att` | G：防备 | E：拥抱 | 第 2 位 |
| 决策主导权 | `lead` | M：我说了算 | A：AI 说了算 | 第 3 位 |

字母含义按产品定义使用，不额外引入 MBTI 的四维解释。

### 7.2 输入与原始分数

输入必须是恰好 12 项的数组，每项为整数 `0 / 1 / 2 / 3`，分别对应 A / B / C / D。缺答、稀疏数组、字符串数字、负数或越界值均拒绝，不自动补答案。

每道题的每个选项有一个三维分数向量，未列出的维度按 0 处理。原始分数为全部 12 个选项的对应维度之和。

### 7.3 平分处理

对每个维度独立执行：

1. 原始总分不等于 0：直接用总分判断方向。
2. 原始总分等于 0：只累计该维度中绝对值恰好为 2 的选项分值，用强选项累计值判断方向。
3. 强选项累计仍为 0：`rel` 默认 T，`att` 默认 E，`lead` 默认 M。

准确判定表达式为：关系判定值大于 0 得 P，否则 T；态度判定值大于等于 0 得 E，否则 G；主导权判定值大于 0 得 A，否则 M。

### 7.4 隐藏款规则

初步类型为 TEM 时，必须同时满足原始分数 `rel ≤ -1`、`att ≥ 1`、`lead ≤ -1` 才保留 TEM，标记为隐藏款。

若条件不满足，从三个原始分数中选绝对值最小的维度转型；绝对值相同按 `rel → att → lead` 优先顺序决定。

| 最弱维度 | 转型结果 |
| --- | --- |
| rel | PEM |
| att | TGM |
| lead | TEA |

转型只改变类型和稀有度，不修改原始分数或坐标。

隐藏款不是随机抽奖，也不检查用户次数或付费状态。固定答案固定命中。配置中的隐藏款 3%～6%、普通类型各 8%～25% 是随机答题模拟的开发校准目标，不是对真实用户分布的承诺；前台不展示伪造的“击败用户百分比”。

### 7.5 结果坐标

- `x = rel / 24`，左为工具，右为伙伴。
- `y = att / 24`，上为拥抱，下为防备。
- 主导权不进入二维图，用“我说了算”或“AI 说了算”标签表示，取最终类型第 3 位。
- 24 是固定归一化分母，不按当前题库实际最大最小值动态拉伸。
- 前端绘图将 x、y 裁剪至 -1～1；横向位置为 `(x + 1) × 50%`，纵向位置为 `(1 - y) × 50%`。
- 非有限数值不画误导点位，显示坐标不可用状态。
- 因平分或隐藏款转型存在，不能仅凭坐标象限反推出最终类型。

## 8. 个人结果页需求

### 8.1 内容顺序

1. AITI 品牌与“你的风格身份”标签。
2. 身份卡：角色图形、三字母代码、类型名、一句话标语、简短人设；只有 TEM 展示“隐藏款”标记。
3. “一句话点评”：点评内容和来源标签。
4. “使用建议”：编号 1～3 的三条建议。
5. “相处坐标”：个人二维点位和主导权标签。
6. “更多解读”：默认收起。
7. 如有有效邀请，显示配对加载提示、失败提示或双人卡。
8. 娱乐免责声明；不能带结果分享时显示降级说明。
9. 固定底部操作栏：“保存海报”“分享给好友”“重新测试”。

### 8.2 读取结果

读取本地最近一次完整记录，校验版本为 1，并从原始 `answers` 重新计分，不能直接信任缓存的类型或坐标。旧记录没有请求 ID 时补充请求 ID。读取错误、答案损坏、版本不支持或没有记录时显示空态：

- 标题：“还没找到你的风格身份”。
- 说明：“先完成 12 个选择，再来看看属于你的解读。”。
- 操作：“开始测试”“返回首页”。

### 8.3 更多解读

| 内容 | 数量或规则 |
| --- | --- |
| 你的优势 | 两条静态内容 |
| 容易踩的坑 | 两条静态内容 |
| 你的名场面 | 一段情景描写 |
| 最配 | 类型名称，配置理由非空时展示理由 |
| 最不配 | 类型名称，配置理由非空时展示理由 |
| 互相不服气 | “你瞧不上”和“瞧不上你的”，各关联一个类型及可选理由 |

这组编辑配置不是双人配对算法的推导结果，不保证“最配”互相指向，也不自动形成互斥或排名。类型引用与完整文案见附录。

### 8.4 隐藏款揭晓

TEM 进入结果页后播放一次约 1200 毫秒的翻转、缩放和粒子效果，显示“隐藏身份，已解锁”以及“跳过揭晓”。点击跳过、切到后台或页面卸载时立即清理计时器。普通类型无该动画。

这里的“一次”指本次结果页面实例一次，不是账号生命周期一次；重新创建页面可再次播放。

### 8.5 解读来源状态

| 状态 | 前台标识 | 内容来源 | 可携带结果分享 |
| --- | --- | --- | --- |
| 加载中 | 正在生成解读… | 点评、建议显示骨架 | 暂不可，按普通邀请处理 |
| model | AI 生成 | 模型返回且通过校验 | 还需满足落库与 rid 条件 |
| mock | 示例解读 | 预置内容，本地模拟或云端无模型 | 本地模拟不可；云端已落库则可以 |
| fallback | 预设解读 | 模型失败、内容不合格或云端更新失败后的静态内容 | 有有效已落库 rid 时可以 |

## 9. AI 内容生成需求

### 9.1 AI 的职责

模型只输出一句点评和恰好三条使用建议，不决定类型，不修改分数，不返回好友信息。输出目标是结合用户具体选择，犀利、有趣、简短且不伤人，不做诊断、不提供危险建议。

### 9.2 模型输入

系统提示词见附录。用户消息按以下内容拼接：

1. `用户的 AI 使用风格：类型名称 (类型代码)`。
2. `特点：当前类型的 persona`。
3. `用户选择：`。
4. 按题序逐行拼接“题干 + 空格 + 用户所选选项文本”。

不向模型发送 OPENID、rid、fromRid、请求 ID 或客户端额外字段。当前没有用户自由输入、联网搜索、检索增强或多轮对话。

### 9.3 返回格式与校验

```json
{
  "roast": "结合本次答案的一句点评",
  "tips": ["建议一", "建议二", "建议三"]
}
```

- 必须可解析为 JSON 对象，不接受代码围栏或 JSON 前后的解释文字。
- 模型文本长度不得超过 4096 个 JavaScript 字符串长度单位。
- 点评去除首尾空白后非空，最多 60 个 Unicode 码点，且不能以“你是”开头。
- 建议必须恰好 3 条，每条去除首尾空白后非空，最多 60 个 Unicode 码点。
- 检查前移除空白、零宽字符并转小写；命中任一屏蔽词即整份不通过。
- 屏蔽词初始表见附录，当前仅为本地字符串过滤，不等于已接入完整平台内容审核。
- 额外 JSON 字段不进入最终输出；实际校验提取 `roast` 和 `tips`，不因多余键本身拒绝响应。

### 9.4 生成与降级时序

1. 服务端验证 12 题答案，重新计分，并校验客户端提交的类型与计算结果一致。
2. 从可信云调用上下文获取 OPENID；缺失时拒绝生成。
3. 先向数据库写入一条完整静态兜底记录，取得独立 rid。
4. 若为云端 mock，直接采用示例内容；否则调用模型。
5. 模型最多尝试 2 次，每次最多等待 2.8 秒；第一次失败或不合格再尝试一次。
6. 合格则更新为模型内容；两次失败则保留静态内容。
7. 最终数据库更新失败时，返回与初次写入一致的静态内容及 fallback 来源。
8. 若存在合法 fromRid，查询对方记录并提取合法类型为 pairCode。
9. 返回 rid、内容、来源及可选 pairCode。

前端解读服务总等待上限为 8 秒，到期显示 offline 内容。迟到的云响应不能再覆盖已显示兜底，也不能覆盖下一轮结果。前端超时不会撤销云函数，云端可能继续完成记录；前端没有拿到 rid 时不能伪造分享 ID，也没有自动查询找回该记录的流程。

### 9.5 缓存与成本边界

- 同一请求 ID 在前端复用进行中的 Promise 和完成内容，答题页与结果页共享同一次任务。
- 存储中已有合格、同类型解读时复用，不自动生成新点评。
- 缓存更新前检查本地最新 requestId 与本轮一致。
- 请求 ID 只在前端关联，不作为服务端幂等键；云端每次实际调用都会新增结果记录。
- 当前没有服务端去重、账号限流、费用额度、滥用控制或运营监控后台。以上可列为上线强化项，不能写成已有能力。
- 模型输出本身具有不确定性，真实 AI 文案不要求逐字复现；分类和静态兜底要求确定性复现。

## 10. 好友配对需求

### 10.1 展示门槛

必须同时满足：本轮有合法 `fromRid`；本人内容 `persisted=true` 且有合法 rid；云端返回有效 pairCode；重新查询好友公开结果成功；好友最新类型等于 pairCode。

不满足任意条件时不拼造双人结果。邀请存在但不可用时显示：“暂时无法读取朋友的结果，先看看你自己的类型吧。”。个人结果和个人操作继续可用。

### 10.2 配对算法

逐位比较两人的三字母类型，差异数量为 `level`，范围 0～3。基础关系如下，完整文案见附录：

| 不同字母数量 | 基础关系 |
| --- | --- |
| 0 | 镜像人 |
| 1 | 最佳搭子 |
| 2 | 互看不惯 |
| 3 | 宿敌 CP |

level 为 1 时，根据差异出现在关系、态度或主导权，选用对应互补文案。若命中特殊组合，以特殊组合名称和文案覆盖基础关系，但 level 仍为实际不同字母数量。

### 10.3 双人卡内容

标题“你们的 AI 相处方式”；显示“你 · 本人类型”和“朋友 · 对方类型”；展示关系名及说明；下方“你们的 AI 坐标”绘制两人点位和连线。

本人使用实心点，朋友使用圆环；坐标相同时重合显示，说明“你们在这两个维度上重合，圆环代表朋友。”。页面连线使用 41 个均匀分布点构成。朋友主导权不作为第三维显示。

操作为“保存双人海报”和“分享你们的配对”。双人分享使用本人的 rid，下一位受邀者与本人建立新关系。

### 11.6 导出、保存与权限

1. 点击保存进入加载状态，个人与双人共用保存锁，阻止重复任务。
2. 获取 Canvas 节点，最多等待 3 秒；图片各最多等待 2.5 秒，失败后使用占位。
3. 绘制并导出 PNG；保存临时文件路径供本页后续复用。
4. 绘制结束或失败都将画布缓冲释放为 1 × 1；保留导出的文件路径。
5. 保存前调用隐私授权流程，再检查相册权限并调用保存。
6. 成功提示“海报已保存到相册”。导出或普通保存失败提示“保存失败，请稍后重试”，解除锁定。
7. 相册权限拒绝时显示“允许保存海报”弹层，提供“前往设置”和“暂不保存”。
8. 用户在设置授权后返回，需重新点击保存，不自动再次执行保存。
9. 页面退出后停止后续相册操作及页面更新，释放未完成的隐私授权回调。

隐私弹层包括“阅读隐私保护指引”“同意并继续”“暂不保存”。同意必须由用户明确操作，拒绝或退出不能视作同意；拒绝提示“请先同意隐私保护指引，再保存海报。”。

### 11.7 8K 能力的准确范围

代码支持 4318 × 7680 PNG，以标准坐标缩放重绘，导出后核对实际图片尺寸，清理大画布；个人/双人及两种清晰度分别缓存。

但是当前结果页模板没有“标准 / 8K 超清”切换按钮，默认值为 standard，因此普通用户路径只能保存标准海报。若后续开放入口，需补充模板绑定、禁用态、8K 失败后手动切回标准的流程，并进行目标设备验收。当前代码没有自动切回标准并重试。

| createdAt | number | 客户端毫秒时间戳 |
| requestId | string | 本轮前端请求关联标识，避免跨轮覆盖 |
| fromRid | string，可选 | 本轮邀请人的结果ID |
| content | object，可选 | 完成后的解读缓存 |

content 包含 `code`、`rid`、`persisted`、`source`、`roast`、`tips` 及可选 `pairCode`。本地 mock 或 offline 的 rid 为空字符串、persisted 为 false。

### 13.2 云端数据集合

集合名 `results`，由管理者在云数据库控制台手动创建。每次真实 genContent 调用新增一条记录，不用 OPENID 作为文档 ID 覆盖历史。

| 字段 | 类型/来源 | 用途 |
| --- | --- | --- |
| _id | 数据库生成 | 分享用 rid |
| _openid | 云上下文OPENID，服务端显式写入 | 关联创建者，不接受客户端身份 |
| code | 服务端重新计分 | 合法类型 |
| scores | 服务端重新计分 | 三维原始分数 |
| answers | 校验后的12项数组 | 完整答案 |
| roast | string | 静态或模型点评 |
| tips | string[3] | 三条建议 |
| source | mock / fallback / model | 内容来源 |
| fromRid | string | 邀请ID或空字符串 |
| createdAt | 数据库服务端时间 | 创建时间 |

coords、rarity、requestId 和 pairCode 不作为当前云端结果记录的持久化字段。offline 是客户端状态，不是云端正常写入来源。

客户端数据库权限为 read=false、write=false；通过云函数处理写入和白名单读取。当前查询按 ID 读取，不需要额外业务查询索引。

### 13.3 genContent 接口

通过 `wx.cloud.callFunction` 调用，名称 `genContent`。

```json
{
  "code": "TEM",
  "answers": [0, 2, 3, 2, 1, 1, 2, 2, 0, 1, 1, 3],
  "fromRid": ""
}
```

成功结构：

```json
{
  "ok": true,
  "rid": "result_demo_001",
  "roast": "提示词像操作手册，连 AI 看了都想申请岗前培训。",
  "tips": ["先写清目标和验收标准，再补背景。", "关键事实仍要核查原始出处。", "保留有效提示词，减少重复调试。"],
  "source": "mock"
}
```

上例 rid 为符合格式的示例，实际必须使用数据库返回的 ID。存在有效邀请时可额外返回 `"pairCode":"TEA"` 等对方类型；fromRid 为空时省略 pairCode。`persisted` 与 content.code 由客户端接到合格成功响应后组装，不是该云函数必返字段。

| 失败码 | 条件 |
| --- | --- |
| INVALID_INPUT | 答案不合法或提交类型与重算结果不一致 |
| UNAUTHENTICATED | 云调用上下文缺少OPENID |
| DATABASE_WRITE_FAILED | 初始记录未能写入，或数据库返回非法ID |

失败结构为 `{"ok":false,"error":"错误码"}`。模型失败有静态兜底，不直接作为该接口失败返回。

### 13.4 getResult 接口

名称 `getResult`，输入 `{"rid":"合法结果ID"}`。成功仅返回：

```json
{
  "code": "TEM",
  "scores": {"rel": -1, "att": 1, "lead": -1}
}
```

公开结果校验：类型必须属于8种之一；三个分数必须为整数，绝对值均不大于24。缺失记录、非法ID、数据库异常、诊断记录或畸形内容均返回 null。

不返回 OPENID、答案、AI 内容、时间或完整数据库对象。这里“公开”指持有结果ID者可读取这组白名单数据，并非仅好友关系内可见。

### 13.5 ping 接口

普通输入 `{}` 返回 `{"ok":true,"message":"ok","database":"unchecked"}`。输入 `{"checkDatabase":true}` 时要求服务端 `ENABLE_M0_DIAGNOSTICS=true`，使用固定文档 `m0-healthcheck` 写入与读回，避免重复新增诊断记录。

诊断成功返回 database=ok；开关未开返回 DIAGNOSTICS_DISABLED；数据库异常返回 DATABASE_CHECK_FAILED；读回异常返回 READBACK_FAILED。诊断不包含用户答案或身份，业务读取会将其排除。

9. 先用云端 mock 验证真实落库、rid 查询和两账号配对，再配置模型。

### 14.4 模型配置

| 服务端变量 | 用途 |

## 16. 异常状态总表

| 页面退出后请求返回 | 无界面更新 | 不污染下一轮 |

| 分享意愿 | 点击分享或触发分享回调次数；不命名为已成功发送人数 |

## 19. 推荐复现顺序

1. 建立原生三页、配置目录、全局视觉及两个组件。
2. 录入附录完整内容，实现评分和配对纯函数，先通过确定性样例。
3. 完成首页、答题、最近结果存储、结果展示与异常恢复。
4. 以mock内容打通个人分享邀请、标准海报和隐私授权。
5. 部署云函数，用云端mock验证真实rid与两账号配对。
6. 接入真实模型与输出验证，测试超时和晚到响应。
7. 对照视觉资源与当前行为完成回归，并单独关闭上线缺口。

以“相同答案得到相同类型、原始分数、坐标和配对；页面状态、内容及分享路径符合本文”为业务复现标准；以实际微信端视觉和互动验收为用户体验交付标准。
